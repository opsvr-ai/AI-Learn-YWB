# 持久化记忆

Hermes Agent 拥有有限的、经过精心策划的记忆，可在不同会话间持久保存。这让它能够记住你的偏好、项目、环境以及它学到的东西。

## 工作原理

两个文件构成了 Agent 的记忆：

| 文件 | 用途 | 字符限制 |
|------|---------|------------|
| **MEMORY.md** | Agent 的个人笔记 — 环境信息、约定、学到的内容 | 2,200 字符（约 800 tokens） |
| **USER.md** | 用户画像 — 你的偏好、沟通风格、期望 | 1,375 字符（约 500 tokens） |

两者都存储在 `~/.hermes/memories/` 中，并在会话开始时作为冻结快照注入到系统提示词中。Agent 通过 `memory` 工具管理自己的记忆 — 它可以添加、替换或删除条目。

:::info
字符限制确保记忆保持精炼。当记忆已满时，Agent 会合并或替换条目以腾出空间给新信息。
:::

## 记忆在系统提示词中的呈现方式

在每个会话开始时，记忆条目从磁盘加载并渲染为系统提示词中的一个冻结块：

```
══════════════════════════════════════════════
MEMORY（你的个人笔记）[67% — 1,474/2,200 字符]
══════════════════════════════════════════════
用户的项目是位于 ~/code/myapi 的 Rust Web 服务，使用 Axum + SQLx
§
本机运行 Ubuntu 22.04，已安装 Docker 和 Podman
§
用户偏好简洁的回复，不喜欢冗长的解释
```

该格式包含：
- 显示所属存储（MEMORY 或 USER PROFILE）的标题头
- 使用百分比和字符计数，以便 Agent 了解容量
- 以 `§`（分节符）分隔的各个条目
- 条目可以多行

**冻结快照模式：** 系统提示词注入在会话开始时捕获一次，会话期间不会更改。这是有意为之 — 它保留了 LLM 的前缀缓存以获得更好的性能。当 Agent 在会话中添加/删除记忆条目时，更改会立即持久化到磁盘，但不会出现在系统提示词中，直到下一次会话开始。工具响应始终显示实时状态。

## Memory 工具操作

Agent 使用 `memory` 工具执行以下操作：

- **add** — 添加一条新的记忆条目
- **replace** — 用更新后的内容替换现有条目（通过 `old_text` 进行子串匹配）
- **remove** — 删除不再相关的条目（通过 `old_text` 进行子串匹配）

没有 `read` 操作 — 记忆内容会在会话开始时自动注入到系统提示词中。Agent 将它的记忆作为对话上下文的一部分来查看。

### 子串匹配

`replace` 和 `remove` 操作使用简短且唯一的子串匹配 — 你不需要完整的条目文本。`old_text` 参数只需要是一个能够唯一标识某一条目的子串：

```python
# 如果记忆中有 "用户在所有编辑器中使用深色模式"
memory(action="replace", target="memory",
       old_text="深色模式",
       content="用户在 VS Code 中使用浅色模式，在终端中使用深色模式")
```

如果该子串匹配到多个条目，则返回错误，要求提供更精确的匹配。

## 两个目标的解释

### `memory` — Agent 的个人笔记

用于 Agent 需要记住的关于环境、工作流程和经验教训的信息：

- 环境信息（操作系统、工具、项目结构）
- 项目约定和配置
- 发现的工具怪癖和变通方法
- 已完成任务的日志条目
- 行之有效的技能和技巧

### `user` — 用户画像

用于关于用户身份、偏好和沟通风格的信息：

- 姓名、角色、时区
- 沟通偏好（简洁还是详尽、格式偏好）
- 忌讳和需要避免的事情
- 工作流习惯
- 技术水平

## 该保存什么 vs 该跳过什么

### 应保存（主动保存）

Agent 会自动保存 — 你无需提出要求。它在学到以下内容时保存：

- **用户偏好：** "我更喜欢 TypeScript 而不是 JavaScript" → 保存到 `user`
- **环境信息：** "这台服务器运行 Debian 12，配备 PostgreSQL 16" → 保存到 `memory`
- **纠正：** "不要对 Docker 命令使用 `sudo`，用户在 docker 组中" → 保存到 `memory`
- **约定：** "项目使用 tab 缩进、120 字符行宽、Google 风格的 docstring" → 保存到 `memory`
- **已完成的工作：** "于 2026-01-15 将数据库从 MySQL 迁移到 PostgreSQL" → 保存到 `memory`
- **明确要求：** "记住我的 API Key 每月轮换一次" → 保存到 `memory`

### 应跳过

- **琐碎/显而易见的信息：** "用户询问了 Python" — 太模糊，没有用
- **容易重新发现的事实：** "Python 3.12 支持 f-string 嵌套" — 可以通过网络搜索获取
- **原始数据转储：** 大块代码、日志文件、数据表 — 对记忆来说太大了
- **会话特定的临时信息：** 临时文件路径、一次性调试上下文
- **上下文文件中已有的信息：** SOUL.md 和 AGENTS.md 的内容

## 容量管理

记忆有严格的字符限制，以保持系统提示词的精简：

| 存储 | 限制 | 典型条目数 |
|-------|-------|----------------|
| memory | 2,200 字符 | 8-15 条 |
| user | 1,375 字符 | 5-10 条 |

### 记忆已满时会发生什么

当你尝试添加一个会超出限制的条目时，工具会返回错误：

```json
{
  "success": false,
  "error": "Memory at 2,100/2,200 chars. Adding this entry (250 chars) would exceed the limit. Replace or remove existing entries first.",
  "current_entries": ["..."],
  "usage": "2,100/2,200"
}
```

Agent 应执行以下操作：
1. 读取当前条目（显示在错误响应中）
2. 识别可以删除或合并的条目
3. 使用 `replace` 将相关条目合并为更短的版本
4. 然后 `add` 新的条目

**最佳实践：** 当记忆使用量超过 80% 容量时（可在系统提示词标题中看到），在添加新条目之前先合并现有条目。例如，将三个独立的"项目使用 X"条目合并为一个全面的项目描述条目。

### 良好记忆条目的实际示例

**紧凑、信息密集的条目效果最好：**

```
# 好的：打包了多个相关事实
用户使用 macOS 14 Sonoma，使用 Homebrew，安装了 Docker Desktop 和 Podman。Shell：zsh 配合 oh-my-zsh。编辑器：VS Code 使用 Vim 键位绑定。

# 好的：具体、可执行的约定
项目 ~/code/api 使用 Go 1.22，sqlc 做数据库查询，chi 路由器。用 'make test' 运行测试。CI 通过 GitHub Actions。

# 好的：带上下文的经验教训
预发布服务器（10.0.1.50）需要使用 SSH 端口 2222 而非 22。密钥位于 ~/.ssh/staging_ed25519。

# 差的：太模糊
用户有一个项目。

# 差的：太啰嗦
2026 年 1 月 5 日，用户让我查看他们位于 ~/code/api 的项目。我发现它使用 Go 1.22 版本，并且...
```

## 重复预防

记忆系统会自动拒绝完全重复的条目。如果你尝试添加已存在的内容，它会返回成功并附带"未添加重复项"的消息。

## 安全扫描

记忆条目在被接受之前会经过注入和泄露模式扫描，因为它们会被注入到系统提示词中。匹配威胁模式（提示词注入、凭据泄露、SSH 后门）或包含不可见 Unicode 字符的内容会被阻止。

## 会话搜索

除了 MEMORY.md 和 USER.md，Agent 还可以使用 `session_search` 工具搜索其过去的对话：

- 所有 CLI 和消息传递会话都存储在 SQLite（`~/.hermes/state.db`）中，具备 FTS5 全文搜索
- 搜索查询直接从数据库返回实际消息 — 无 LLM 摘要、无截断
- Agent 可以找到几周前讨论的内容，即使这些内容不在其活动记忆中
- Agent 还可以在找到的任何会话中前后滚动浏览

```bash
hermes sessions list    # 浏览过去的会话
```

有关三种调用形态（发现/滚动/浏览）和响应格式，请参阅[会话搜索工具](/docs/user-guide/sessions#session-search-tool)。

### session_search vs memory

| 特性 | 持久化记忆 | 会话搜索 |
|---------|------------------|----------------|
| **容量** | 总共约 1,300 tokens | 无限制（所有会话） |
| **速度** | 即时（在系统提示词中） | 约 20ms FTS5 查询，约 1ms 滚动 |
| **成本** | 每次提示都消耗 token | 免费 — 无需 LLM 调用 |
| **用例** | 始终可用的关键事实 | 查找特定的过往对话 |
| **管理** | 由 Agent 手动整理 | 自动 — 所有会话均已存储 |
| **Token 成本** | 每次会话固定（约 1,300 tokens） | 按需（需要时搜索） |

**记忆** 适用于应始终在上下文中的关键事实。**会话搜索** 适用于"我们上周讨论过 X 吗？"这类查询，Agent 需要回忆过去对话中的具体细节。

## 配置

```yaml
# 在 ~/.hermes/config.yaml 中
memory:
  memory_enabled: true
  user_profile_enabled: true
  memory_char_limit: 2200   # 约 800 tokens
  user_char_limit: 1375     # 约 500 tokens
```

## 外部记忆提供者

对于超出 MEMORY.md 和 USER.md 范围的更深层、持久化记忆，Hermes 内置了 8 个外部记忆提供者插件 — 包括 Honcho、OpenViking、Mem0、Hindsight、Holographic、RetainDB、ByteRover 和 Supermemory。

外部提供者**与**内置记忆同时运行（绝不会替代内置记忆），并增加了知识图谱、语义搜索、自动事实提取和跨会话用户建模等能力。

```bash
hermes memory setup      # 选择一个提供者并配置
hermes memory status     # 检查当前激活状态
```

有关每个提供者的完整详细信息、设置说明和对比，请参阅[记忆提供者](./memory-providers.md)指南。
